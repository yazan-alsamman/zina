# Implementation Architecture

**Status:** Phase 4. The production foundation.

**What exists:** an Astro application with one fully implemented template — the review page — plus
a 404, a global shell, five signature devices, a bilingual content layer and a test suite.

**What does not:** every other route. That is deliberate. The review page is the proving ground;
if the foundation could not reproduce it faithfully, expanding to other routes would multiply the
error.

---

## 1. Technology decisions

| Decision | Choice | Why |
|---|---|---|
| **Framework** | **Astro 5.18** | Ships zero JavaScript by default, which is the exact requirement of a site whose densest content is static evidence. Content collections, file-based routing and per-component scoped CSS come free |
| **Language** | **TypeScript, strict** | Plus `noUncheckedIndexedAccess` and `verbatimModuleSyntax`. The content model is a partial map keyed by locale; without `noUncheckedIndexedAccess` a missing translation reads as a runtime `undefined` rather than a compile error |
| **Output** | **Static** | Every page here is a document. Nothing needs a server at request time. The one exception — `/` locale negotiation — is host configuration, not application code |
| **Styling** | **Plain CSS with custom properties** | The design system is 12 token groups and ~20 components. A utility framework would add a build step, a class vocabulary and a bundle to solve a problem this size does not have |
| **UI framework** | **None** | No React, Vue, Svelte, Solid. Nothing on the review page has client state |
| **Animation library** | **None** | Five CSS patterns. Budget was 3KB; actual is 0KB, because the two entrance animations that survived are CSS keyframes |
| **Fonts** | **Self-hosted, generated by a script** | See `docs/PERFORMANCE_IMPLEMENTATION.md` §2 |
| **Icons** | **None yet** | The review page needs none. The nine-icon set ships when a surface needs one |
| **Testing** | **`node --test`, zero dependencies** | Node 24 strips TypeScript natively, so the same modules the bundler compiles are the ones the tests import |

**Total production dependencies: 6** — `astro` plus five `@fontsource` font packages (SIL OFL 1.1
assets, not code). **Dev dependencies: 2** — `@astrojs/check`, `typescript`.

**No prohibited dependency was added.** No React, Vue, Svelte, Solid, Tailwind, Bootstrap, MUI,
component library, animation library, WebGL, Three.js, GSAP, Framer Motion, or state manager.

## 2. Project structure

```
astro.config.mjs          static output, trailingSlash always, site (placeholder — U-01)
tsconfig.json             strict + noUncheckedIndexedAccess + verbatimModuleSyntax
package.json              6 deps, 2 dev deps

content/                  UNCHANGED FROM PHASE 1 — the schema and the mock layer
  schema/types.ts           the contract. Phase 4 imports it; it does not restate it
  mock/*.json               11 collections, 42 records

src/
  lib/                    the only place that knows how things work
    content.ts              content access, lifecycle, locale, gates          (~300 lines)
    routing.ts              paths, canonicals, hreflang, switcher, breadcrumbs
    seo.ts                  metadata and JSON-LD builders
    bidi.ts                 THE PHASE 3 CORRECTION — numeral isolation
    ui-strings.ts           interface chrome, both locales, typed
  types/
    site.ts                 narrows the `unknown` fields of the Phase 1 SiteConfig
  styles/
    tokens.css              Phase 2 design tokens, 1:1 with DESIGN_TOKENS_SPEC.md
    global.css              reset, document, 4 layout primitives, 4 type helpers
  layouts/
    BaseLayout.astro        <html lang dir>, head, fonts, landmarks
  components/
    shell/                  SiteHeader, SiteFooter, LocaleSwitcher, SkipLink, Breadcrumbs
    devices/                THE FIVE SIGNATURE DEVICES
    review/                 review-specific composition
    media/                  Frame — the image primitive
  pages/
    [locale]/reviews/[slug].astro    THE REVIEW PAGE
    [locale]/404.astro

public/fonts/             GENERATED by scripts/build-fonts.mjs — woff2 + per-locale CSS + licences
scripts/build-fonts.mjs   font pipeline with a budget check that fails the build
tests/                    98 tests: bidi, content/routing, build output
tools/                    UNCHANGED — the four Phase 0–3 validators
```

### Why this shape

**`src/lib/` is the whole architecture.** Templates ask questions (`reviews("ar")`,
`brandPassesGate(brand, locale)`) and render answers. No template computes a gate, filters a
locale, or builds a URL from string concatenation. That is what makes adding the next five
templates cheap, and what makes the rules enforceable in one place.

**Components are grouped by role, not by type.** `devices/` holds the five things that make this
site look like itself; `shell/` holds the things every page has; `review/` holds composition that
is not yet proven to be reusable. When the Method page needs the observation timeline, it moves
out of `review/`. **Nothing was abstracted before a second use case existed.**

**`content/` was not touched.** The Phase 1 schema, the mock data and the four validators are
exactly as Phase 3 left them. Phase 4 reads them; it does not reshape them.

**Rejected: Astro content collections (`src/content/`).** The idiomatic Astro 5 approach would
define zod schemas and a `file()` loader. It was rejected because it would create a **second
schema definition** alongside `content/schema/types.ts`, validated by a **second validator**
alongside `tools/validate-content.mjs`. Two schemas drift, and the drift would be invisible until
a build broke. The existing contract already has three phases of decisions in it. See D4-2.

## 3. The layered model

```
  content/mock/*.json          data
        │
  content/schema/types.ts      the contract  ─────────────┐
        │                                                 │
  src/lib/content.ts           access + lifecycle + gates │  no template
        │                                                 │  reaches past
  src/lib/{routing,seo,bidi,ui-strings}.ts   derivation   │  this line
        │                                                 │
  ────────────────────────────────────────────────────────┘
        │
  src/components/**            presentation only
        │
  src/pages/**                 composition + route generation
```

**Rules the layering enforces:**

1. A component never imports from `content/mock/`.
2. A component never decides whether something is publishable.
3. A page never builds a URL by string concatenation.
4. Nothing below `lib/` knows what a lifecycle state is.

## 4. CSS architecture

Three levels, and no framework.

| Level | File | Contains |
|---|---|---|
| **Tokens** | `styles/tokens.css` | Values only. No selectors except `:root` and the locale root |
| **Global** | `styles/global.css` | Reset, element defaults, **four** layout primitives, **four** type helpers |
| **Component** | `*.astro` `<style>` | Everything else, scoped by Astro |

**Four layout primitives, and each earns its place by appearing on every template:**
`.container` (1180px cap) · `.text-column` (66ch maximum, not a fixed width) · `.full-bleed` ·
`.section` (rhythm token).

**Four type helpers:** `.display-lg`, `.display-md`, `.label`, `.record`.

**No magic numbers.** Every length in a component style is a token or a ratio. The only literals
are `6px` (the mineral square, which is a mark rather than a measure) and `2px` (the plate-pair
gap, which is deliberately hairline-sized).

### RTL

**Logical properties throughout.** `margin-inline`, `padding-inline-start`, `border-inline-start`,
`inset-inline`, `text-align: start/end`. There is **no second stylesheet for Arabic** and no
`[dir="rtl"]` override block anywhere in the codebase — the one direction-aware rule that existed
(a `translateX` for full-bleed) was deleted when full-bleed stopped needing a breakout.

The whole Arabic layout is produced by two things: `dir="rtl"` on `<html>`, and two custom
properties re-declared at the locale root.

## 5. What is intentionally absent

| Absent | Why |
|---|---|
| A `Card` component | The index treatment replaces it. Three contained surfaces exist and each is documented |
| A component library | Every component maps to a content entity or a named UX requirement |
| Client-side JavaScript | **0 bytes shipped.** The mobile menu is a checkbox disclosure |
| A CSS framework | 12 token groups and 20 components do not need one |
| `src/content/` collections | Would duplicate the Phase 1 schema. D4-2 |
| A homepage | Explicitly out of scope for Phase 4 |
| Sitemap generation | Phase 8. Emitting one now would advertise a site with one template |
| An analytics integration | Phase 11, and it is a privacy decision blocked on U-03 |
| `astro:assets` image optimisation | **No photography exists.** The `Frame` component reserves ratio and renders the documented no-photography state. Swapping in `<Image>` is a change to one file |

## 6. Build and verification commands

```bash
npm run dev                # astro dev
npm run build              # astro build      → dist/, 12 pages
npm run check              # astro check      → type checking
npm run test               # node --test      → 98 tests
npm run validate:content   # Phase 1 validator
npm run validate:contrast  # Phase 2 contrast tool, 24 pairs
npm run validate:ux        # Phase 3 UX coverage checker
npm run guard:mock         # scans dist/ — MUST FAIL while the source is mock
node scripts/build-fonts.mjs   # regenerate font assets; fails if a locale exceeds 180KB

npm run verify             # the full chain, in order
```

`npm run verify` **fails today, at the last step, by design**: the mock guard blocks a build made
from the mock content layer. That is the pipeline working, not a broken pipeline.

## 7. Known architectural limitations

1. **Links to unbuilt routes resolve to 404.** The breadcrumb, header, footer and Method link all
   point at routes Phase 4 did not build. The paths are correct and centralised in
   `routing.ts`; they start working as each template lands. `NOT_YET_IMPLEMENTED` lists them.
2. **`site` is a placeholder domain** (`https://example.invalid`). Canonical and hreflang URLs are
   structurally correct and factually wrong until U-01 is answered. The invalid TLD is chosen so a
   placeholder can never be mistaken for a real domain.
3. **No `/` route.** Root locale negotiation is a 302 by `Accept-Language`, which a static build
   cannot perform. It is host configuration; see `docs/LOCALE_IMPLEMENTATION.md` §6.
4. **The Frame component does not optimise images**, because there are none to optimise.
5. **Journal bodies are still JSON outlines.** MDX is a Phase 1 decision (D-8) that lands when the
   journal template is built.
